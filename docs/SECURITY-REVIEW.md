## HIGH-SEVERITY ISSUES

### H1: AsyncStorage Backups Can Expose Drafts (RECLASSIFIED)
Severity: HIGH
Location: src/lib/trip-drafts.ts; AndroidManifest.xml line 17
Issue: Device backups to Google Cloud contain unencrypted AsyncStorage
Fix: Set android:allowBackup="false" or exclude AsyncStorage from backup rules

### H2: Orphaned Storage Files on Delete
Severity: HIGH
Location: supabase/migrations/0001_init.sql
Fix: Client deletes files before row delete; post-MVP cleanup job

### H3: Sign-Up Enumeration - Email Reveals Registration  
Severity: HIGH
Location: src/lib/auth-errors.ts lines 86-87
Code: mapSignUpError() returns "An account with this email already exists"
Note: Intentional UX but enables probing
Fix: Rate-limit sign-up to prevent enumeration

### H4: Nominatim Email Is Personal (RECLASSIFIED)
Severity: HIGH  
Location: app.config.ts line 82
Issue: Personal email in app binary and all API requests
Note: Moving to .env doesn't help (still public in bundle + traffic)
Fix: Use project email (support@onmyway.app) instead

### H5: npm Vulnerability - decode-uri-component via expo-router
Severity: HIGH (Low practical risk)
Location: expo-router -> query-string -> decode-uri-component
Runtime vs Build-Time:
  IN RUNTIME: query-string/decode-uri-component (via expo-router)  
  BUILD-TIME ONLY (not shipped): braces, node-forge, uuid
Practical Risk: Low (app doesn't parse untrusted URLs)
Fix: Monitor Expo SDK releases
